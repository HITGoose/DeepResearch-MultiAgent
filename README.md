# 🔬 DeepResearch-Agent 多智能体深度研究系统

基于 LangGraph 的多智能体协作深度研究系统，通过**先模拟再执行（Simulate-Before-Act）**的搜索规划和**多源 NLI 交叉验证**机制，生成带引用的高质量研究报告。

## 架构

```
用户问题 → 规划器 → 搜索器 → 分析器 → 撰写器 → 评审器
             ↑                                      │
             └──── 迭代改进（得分 < 阈值时触发）────┘
```

### 智能体

| 智能体 | 职责 | 核心技术 |
|-------|------|----------|
| **规划器** | 分解问题，生成并评估候选搜索计划 | 先模拟再执行 |
| **搜索器** | 多源搜索（网页 + ArXiv + 维基百科），按子查询依次执行 | 逐条压缩搜索结果 |
| **分析器** | 交叉验证多源信息，检测矛盾 | NLI 矛盾检测 |
| **撰写器** | 生成带引用的研究报告 | 声明级引用追踪 |
| **评审器** | 评估报告质量，决定通过/迭代 | 大模型评审 |

### 核心创新点

**1. 先模拟再执行（Simulate-Before-Act）的搜索规划**

规划器不直接执行搜索，而是先生成多个候选策略，用轻量大模型模拟每个策略的预期覆盖度，选择最优方案再执行。失败的策略在下一轮迭代中被显式排除。

> *参考论文：Simulate Before Act（Gu 等，2025）*

**2. 多源 NLI 交叉验证与冲突消解**

分析器使用自然语言推理（NLI）模型 `cross-encoder/nli-deberta-v3-base` 检测不同来源间的矛盾：把每条声明和其他来源的摘要逐一比较，模型输出经 softmax 转成概率后，支持概率 > 0.75 记为支持、矛盾概率 > 0.9 记为矛盾。报告中每条声明标注置信度：
- ✅ 多源一致（高可信）
- ⚠️ 来源有争议（标注各方立场）
- ❓ 仅单一来源（待验证）

> *针对的问题：DeepHalluBench（2026.01）PIES 分类法中的"显式总结"类幻觉*

### 上下文管理（防止上下文膨胀）

| 策略 | 做法 |
|------|------|
| 智能体之间只传压缩摘要 | 状态中只保存每条结果的摘要和原子声明，不保存原文 |
| 先逐条压缩、再统一综合 | 每条搜索结果先单独压缩，再由分析器统一综合，综合时摘要截断至 3000 字符 |
| 每轮清空搜索结果 | `search_results` 使用自定义合并函数（reducer）：节点返回 `None` 时清空，状态中只保留本轮结果 |
| 文件外挂记忆 | 一次研究的所有轮次共用 `outputs/memory/<run_id>/`：原文和压缩摘要按子查询存储，后续轮次遇到相同子查询直接读回；每轮的分析和来源也存入其中，下一轮读回 |
| 渐进式总结 | 撰写器每轮从头撰写，不累积历史草稿；分析器会读回上一轮的分析并与本轮结果合并，避免补上缺口的同时丢掉已覆盖的内容 |

## 实验结果

### 早期运行记录（修复 NLI 和上下文管理之前的版本）

4 个不同难度的查询，各运行一次（英文报告）：

| 查询任务 | 难度 | 迭代次数 | 最终得分 | 耗时 | ✅ 高可信 | ⚠️ 争议 | ❓ 待验证 |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| MCP 是什么 | 简单 | 2 | 7.4/10 | 432 秒 | 5 | 0 | 19 |
| LangGraph 与 CrewAI 对比 | 中等 | 3 | 7.0/10 | 724 秒 | 4 | 0 | 19 |
| RAG 与微调对比 | 中等 | 2 | 6.85/10 | 411 秒 | 1 | 0 | 23 |
| 大模型智能体的幻觉缓解 | 复杂 | 4（上限） | 5.4/10 | 819 秒 | 0 | 0 | 22 |

- 得分为系统内评审器的自评分（大模型评审，与撰写器使用同一模型），范围 5.4–7.4；复杂查询达到迭代上限仍未通过阈值（6.0）
- NLI 统计为最后一轮的交叉验证结果；"⚠️ 争议 = 0"只说明未标出矛盾

### NLI 修复与测评

**问题**：`CrossEncoder.predict` 对多分类模型默认返回未归一化的分数（logits，如 `[6.83, -3.73, -2.82]`），原代码直接拿它和概率阈值 0.75 / 0.9 比较，阈值实际不起作用，等于只取最高类。修复后先做 softmax，标签顺序从模型的 `id2label` 读取。

**测试集**：`evaluation/nli_testset.json`，44 对（支持 15 / 矛盾 15 / 中立 14），已人工核对标签。前提是模拟搜索器生成的来源摘要，假设是另一来源的原子声明，主题取自项目实际运行过的研究问题（RAG 与微调、幻觉、LangGraph/AutoGen、MCP、RLHF/DPO、LoRA 等）。判定规则与 `cross_verify_claims` 一致。

| 配置 | 准确率 | 矛盾召回 | 矛盾精确率 | 支持召回 | 中立召回 | 误判为矛盾 |
|---|---|---|---|---|---|---|
| 修复前（未归一化分数 + 阈值） | 0.977 (43/44) | 1.000 | 1.000 | 0.933 | 1.000 | 0 |
| 修复后（概率 + 阈值） | 0.977 (43/44) | 1.000 | 1.000 | 0.933 | 1.000 | 0 |

- **修复前后在这个测试集上没有差别**：模型对全部 44 对都很确定（最高类概率最低 0.984），阈值从未起作用。修复保证的是模型没把握时（如最高类只有 0.6）会正确地判为中立，这类情况本测试集没有覆盖。
- 唯一错误是第 7 条：原文是 "reduced hallucination rates by about 40%"，声明把 "reduced" 换成了同义的 "lowered"，模型以 0.999 判为中立。
- 运行：`python -m evaluation.eval_nli`

### 上下文管理修复前后对比

**问题**：
1. `search_results` 用 `operator.add` 合并，`prepare_iteration` 返回 `[]` 只是"旧值 + []"，结果跨轮累积；
2. 文件外挂记忆只写不读，且每轮新建目录。

修复方式见上文上下文管理表。

**对比方法**：3 个固定问题，修复前后各运行 1 次（DeepSeek `deepseek-chat` + Tavily）。两个版本遇到相同查询时使用相同的搜索结果（缓存）。token 为该轮所有大模型调用的输入 + 输出。"终评分"是系统内评审器的最终分，"独立评审"是 `evaluation/judge.py` 的总分（同为 DeepSeek）。

| 问题 | 版本 | 轮数 | 每轮 token | 总 token | 状态中的结果条数 | 终评分 | 独立评审 |
|---|---|---|---|---|---|---|---|
| MCP 是什么 | 修复前 | 1 | 1.83 万 | 1.83 万 | 15 | 7.1 | 7 |
| | 修复后 | 1 | 1.88 万 | 1.88 万 | 15 | 6.6 | 7 |
| LangGraph、AutoGen、CrewAI 对比 | 修复前 | 2 | 1.91 万 / 2.05 万 | 3.95 万 | 15 → 30 | 6.35 | 5 |
| | 修复后 | 1 | 1.86 万 | 1.86 万 | 15 | 7.2 | 7 |
| 幻觉缓解（训练类与提示类方法） | 修复前 | 4（未通过） | 1.80 万 / 2.06 万 / 1.95 万 / 2.25 万 | 8.05 万 | 15 → 30 → 45 → 63 | 5.9 | 5 |
| | 修复后 | 4（第 4 轮通过） | 1.93 万 / 2.16 万 / 1.90 万 / 2.14 万 | 8.14 万 | 15 / 15 / 15 / 15 | 6.2 | 6 |

- **确认的效果**：状态中的搜索结果不再跨轮累积（复杂查询 63 条 → 每轮 15 条）。
- **每轮 token 基本不变**：分析器和撰写器原本就只截取最近 15 / 20 条交给大模型，累积的结果留在状态里，并没有全部发给模型；累积的实际危害是撰写器的来源池混入上一轮结果。读回上一轮分析使分析器每轮多用约 700 token；复杂查询中命中 1 次记忆，省掉 1 次搜索和 3 次摘要调用。
- **评分差异不能归因于修复**：
  - 前两个问题修复后都在第 1 轮通过，修复的代码没有执行到。
  - 第二个问题两个版本使用相同的搜索结果，第 1 轮报告仍分别得到 5.3 和 7.2 分，单次运行的评分波动约 ±2 分。
  - 只有复杂查询走完了多轮，但样本只有 1 次。

### 已知局限

- **NLI 只覆盖英文**：测试集全部是英文，NLI 模型 `nli-deberta-v3-base` 也只支持英文；如果搜索器生成中文摘要，交叉验证基本失效，本测试集测不出这一点。
- **NLI 测试集偏简单**：模型置信度全部 ≥ 0.984，没有覆盖模型没把握的模糊情况。
- **评分受大模型波动影响**：评审器和独立评审都是大模型，且与撰写器使用同一模型；每个配置只运行 1 次，单次波动约 ±2 分，上表的评分差异不具统计意义，需要每个问题多次运行取平均。
- **评审只看报告前 3000 字符**：评审器和 `judge.py` 都会截断报告，后半部分内容不参与评分。
- **复杂查询不收敛**：评审器多轮反复指出相同缺口（如 CoVe、Reflexion、RLHF/DPO），搜索未能找到相关来源，这与上述两个修复无关。

## 快速开始

```bash
# 1. 克隆项目
git clone https://github.com/YOUR_USERNAME/DeepResearch-Agent.git
cd DeepResearch-Agent

# 2. 安装依赖
pip install -r requirements.txt

# 3. 配置 API Key
cp .env.example .env
# 编辑 .env，填入 DeepSeek 和 Tavily 的 API Key

# 4. 运行（示例问题：对比 LangGraph 和 CrewAI 在多智能体开发中的表现）
python main.py "Compare LangGraph and CrewAI for multi-agent development"
```

## 技术栈

| 组件 | 选型 |
|------|------|
| 智能体编排 | LangGraph（StateGraph） |
| 大模型 | DeepSeek API / OpenAI API（可配置） |
| 网页搜索 | Tavily API |
| NLI 模型 | cross-encoder/nli-deberta-v3-base |
| 前端 | Streamlit（可选） |
